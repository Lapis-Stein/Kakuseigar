# 構成方針

この文書は公開できる範囲の構成説明です。ブラウザー内で動作し、[GitHub Pages](https://lapis-stein.github.io/Kakuseigar/)で公開しています。

この文書は、このリポジトリに含まれる実装を説明します。作品絵・拡大表示、立ち絵のWebP化、Xとコピーを選ぶ共有画面、案内役への反応と実績共有、公開ランキング・作品紹介ポップアップ・来訪カウンターを含みます。公開への反映状況は[デプロイ履歴](https://github.com/Lapis-Stein/Kakuseigar/deployments/github-pages)で確認できます。

公開更新時は、`index.html` のCSS・入口JavaScriptと、変更した既存モジュールの参照に付ける版番号も更新します。古いキャッシュと新しい処理が混在することを避けるためです。新規素材は異なるファイル名で参照します。

日本語のアプリ名は「青娥の小説案内」、英字名は `Kakuseigar` です。画面・ブラウザーのタイトル・リンクのプレビュー・共有文でこの表記を使い、共有タグは `#青娥の小説案内 #東方Project` に統一します。会話や紹介文の一般名詞としての「お話」はそのまま使います。

## 画面と処理

質問画面、作品紹介画面、これまで紹介した作品を見返す画面があります。作品紹介からpixivへ移動でき、質問を続けて別の作品を探すこともできます。

| 画面 | URLのhash | 主な操作 |
| --- | --- | --- |
| 開始 | `#/start` | 新しく始める、同じタブの続きから再開する、みんなへのお薦めを見る |
| 通常質問 | `#/play` | 選択式の回答、スキップ、回答のやり直し |
| 人物質問 | `#/favorite` | 1人の人物の活躍を見たいか答える |
| 作品紹介 | `#/result/{resultId}` | 作品を見る、pixivへ進む、別の作品を探す、共有する |
| 紹介履歴 | `#/history` | この回で紹介した作品を選ぶ |
| 過去の作品紹介 | `#/review/{resultId}` | 紹介時の結果を見返す、共有する、今の案内に戻る |
| 今回の関心 | `#/result/{resultId}/answers`、`#/review/{resultId}/answers` | その作品の紹介時点の関心の配分と、青娥の一言を見る |
| 作品の特徴 | `#/result/{resultId}/work`、`#/review/{resultId}/work` | 同じ7項目で作品の持ち味を見る、近い味わいの作品の紹介を開く |
| 最後の会話 | `#/ending` | 作者のXを開く、紹介履歴を見る、遊び直す |
| サイトの説明 | `#/about` | 案内の説明・二次創作の表記・ガイドラインを確認する |
| みんなへのお薦め | `#/stats` | 初回推薦・pixiv本文リンク利用を切り替え、直近7日間と累計のランキング・作品紹介を見る |

共通ヘッダーには作者のX・pixivへのアイコンリンクを置き、リンク先は新しいタブで開きます。フッターには「これまでのお薦め」「このサイトについて」「みんなへのお薦め」「最初から遊ぶ」を置きます。紹介履歴は0件の間は無効にし、利用できる場合は作品数を読み上げ用のラベルにも反映します。

開始画面には案内開始・再開ボタンの横にも「みんなへのお薦め」を置き、フッターの入口を併存させます。ボタン群は12pxの間隔を設けて幅に応じて折り返し、狭い画面では案内開始・再開とランキングのボタンを縦に並べます。

フッターの各項目には青娥の髪飾りをモチーフにした小さなアイコンと、両端が背景へなじむ半透明の明るい帯を添えます。強い枠や塗りつぶしを避けつつ、文字が書斎の背景に埋もれない見た目にします。操作領域は高さ44px以上を確保し、小さい画面では2列に並べます。

ブラウザー内で次の役割を分けます。

1. 質問を表示して回答を受け取る。
2. 回答と公開用データから紹介する作品を選ぶ。
3. 選んだ理由に合う前置きと、作者の既存キャプションを表示する。
4. 回答・出題済みの質問・紹介済みの作品を、その回の進行として保持する。

推薦の計算と画面の言い回しを分け、質問や演出を差し替えやすくします。読者の人格を確定する診断にはしません。

## データの境界

| 公開側 | 非公開の制作資料側 |
| --- | --- |
| サイト本体、動作に必要なデータ | 編集用の正本、検討記録 |
| 公開する設問と選択肢 | 設問や配点の候補、検証結果 |
| 作品タイトル、pixivリンク、公開する紹介文 | 作品本文の分析、結末を含む評価根拠 |

制作資料から許可した項目だけを書き出し、内容を確認して公開側へ取り込みます。実行用データは `data/runtime.json`、画像の対応や表示設定は `data/presentation.json` に配置しています。公開確認前の作品別紹介文は実行用データに含めていません。

配信されたコード、設問、配点、作品への対応は、調べる人には確認できます。非公開にしたい本文の根拠や制作メモは、公開用データへ含めないことで分離します。画面に表示しないだけでは非公開になりません。

## 実装の分担

| ファイル | 役割 |
| --- | --- |
| `src/engine.js` | データ検証、推薦・出題の計算、推薦の前置き |
| `src/session.js` | 回答、紹介済み、寄り道、結果の確定と復帰 |
| `src/app.js` | 画面の表示、操作、履歴、共有、hashによる画面移動 |
| `src/result-insights.js` | 紹介時点の関心、表示用の配分・目盛り、青娥の一言、近い作品の選択 |
| `src/result-details.js` | 関心と作品特徴の詳細2ページ、関連作品の入口の描画 |
| `src/storage.js` | sessionStorageの読書き、データ変更の識別 |
| `src/portraits.js` | 回答や採点と独立した、質問中の立ち絵の抽選 |
| `src/analytics.js` | 公開URLだけで節目を計測し、質問操作は端末内で集計する |
| `src/public-stats.js` | 一度だけ取得した公開集計を、来訪回数・ランキング・足跡として表示する |
| `scripts/export-public-stats.mjs` | Googleから読み取った集計のうち、許可した件数だけを静的JSONへ書き出す |

回答・紹介済み・質問順は同じタブで保持します。データが更新された場合は古い回答を新しい配点で黙って再計算しません。紹介数は読了数として扱いません。

保存先は `sessionStorage` です。`runtime.json` と `presentation.json` の内容を識別値に含め、保存済みの進行と一致しない場合は案内を表示して新しく始められる状態にします。タブを閉じた後の再開は保証しません。結果IDはこの回の履歴を参照するためのもので、別の利用者が開ける結果の公開URLではありません。

人物についての質問は、通常質問の間へ自動で挿入します。青娥を除き、まだ紹介していない対象作品があり、この回でまだ尋ねていない人物から、作品数に重み付けせず1人を抽選します。位置と人物はラウンド作成時に固定し、再読込・履歴の閲覧・通常回答のやり直しでは選び直しません。「はい」はその人物による即時推薦、「いいえ／まだわからない」は採点を変えず通常質問の続きへ戻します。

初回は通常質問2～4問のいずれかの後、継続時は50%の確率で1問の後に挿入する設定です。各ラウンド1回までで、残り通常質問が0～1問の場合や対象人物がいない場合は挿入しません。人物質問は通常質問を消費しません。

質問中の立ち絵は通常・人物質問をまたいで連続しないよう抽選し、その設問を表示している間は固定します。採点や回答値から表情は選びません。PCの右側の枠には最小高さを設け、長文では自然に伸びます。スマホでは青娥をバストアップで表示し、PC用の最小高さは解除します。質問の枠だけは画面の高さを基準に下限を設け、短い人物質問でもスクロール位置を揃えられるようにします。開始・回答・スキップ・回答のやり直し・次の作品探しで質問へ進んだ際は、その質問の枠まで自動スクロールします。動きを減らす設定では即座に移動します。

現在のPC用の最小高さは `42rem` です。画面幅820px以下では縦配置へ切り替え、通常質問と人物質問だけ `calc(100svh - 3rem)` を最小高さにします。結果などの長い画面を固定高さに収める方式にはしません。

## 作品紹介と画像

現在の結果と履歴から開いた結果は、同じ作品カードを使います。作品名、診断による推薦の前置き・理由、作者による紹介、pixivの本文リンクを表示します。既存キャプションは文章と改行を保ち、「作者による紹介」と明示します。

作品絵がある場合は、構図を切り取らずにカードへ置きます。配置は画面幅だけでなく、作品カードの内側の幅で切り替えます。

- 470px以上：幅190pxの絵を左に、作者の紹介と推薦理由・本文リンクを右に置きます。
- 470px未満：幅180pxの絵、推薦理由・本文リンク、作者の紹介の順に縦に置きます。

カードでは小表示用WebPを読み込み、絵を押した時に拡大用画像を読み込みます。拡大はネイティブの `dialog` で表示し、画像全体が見えるように収めます。閉じるボタン・Escキー・ダイアログ外側のクリックで閉じ、操作元にフォーカスを戻します。小表示用画像が読み込めない場合は画像部分を取り除き、紹介と本文リンクを残します。拡大用画像の読込失敗はダイアログ内で案内します。

青娥の立ち絵は原PNGを残したまま透過WebPで表示します。作品絵の対応、画像サイズ、変換手順は[素材の配置](assets.md)を参照してください。

## 関心と作品特徴の詳細

結果カードと紹介履歴から開いた作品カードに「今回の関心を見る」「この作品の特徴を見る」を並べます。長い詳細はポップアップにせず、2つのページを移動する形です。上部に対象作品の小さな画像とタイトル、2ページへのタブ状のリンクを置きます。戻るリンクは入口の作品カードに戻り、紹介履歴から入った場合は履歴側のカードに戻ります。保存された結果がないURLは現在の案内へ戻します。未表示の推薦が準備されている場合も、詳細URLだけで紹介済みにせず、先に作品カードを表示します。

7項目の表示順は、軽妙な掛け合い、駆け引き、技・仕組み・工夫、戦闘・危機の突破、親しみ・関係の近さ、割り切れない選択・余韻、譲れない線・価値観の食い違いで共通です。横棒の配置と色を揃え、数値の意味は欄の上部で分けます。

- **今回の関心**：紹介結果の `answerCount` までの回答だけを使います。作品の好みに関する回答から得た配分を合計100%で示し、人物の行動に関する回答やスキップは混ぜません。表示は整数%とし、端数は合計が100になるよう配分します。回答に表れなかった項目は「—」で示し、苦手や嫌いを意味しません。右端は最大の配分に合わせて20・40・60・80・100%から選び、目盛りは4等分します。該当する回答がまだない場合はその旨を上部に表示し、架空の配分を作りません。
- **作品の特徴**：公開済みの作品データの7項目を「作品の持ち味」「0〜4の目安」として示します。読者の関心の割合とは単位が異なり、作品の品質や診断の適合率を表しません。

後から質問を続けても、以前の結果の関心や一言は紹介時点の内容を保ちます。詳細を開く、タブを切り替える、閉じるといった操作では回答・紹介履歴・全作品紹介の進行を変更せず、解析イベントも送信しません。

両ページは同じレイアウト領域を共有し、その画面幅で長い方に合わせた高さを確保します。非表示のページは操作・読み上げの対象から除外します。切り替えてもウィンドウの幅・高さと下部リンクの位置が変わらず、同じ結果の2ページ間ではスクロール位置を保ちます。狭い画面や文字拡大時には必要な高さまで自然に伸ばし、内容を切り捨てません。数値の下に長い説明注釈は置きません。

### 青娥の勝手な見立て

「今回の関心」の下部に、項目名と青娥の短い台詞を置きます。丸める前の配分の上位2項目を順序なしで組み合わせ、用意した21通りの台詞から選びます。1位と2位が入れ替わっても同じ台詞です。関心をからかう演出であり、人物評価や推薦の採点には使いません。

2位と3位が同率で2項目に決められない場合、正の項目が1つだけの場合、該当する回答がない場合には、それぞれ専用の台詞を使います。台詞はサイト内に保持し、外部AIへの問い合わせや追加の解析送信はありません。ローカルMockの文案一覧・仮の配分・表示見本の帯は公開物に含めません。

### 近い味わいのお話

「作品の特徴」の下部に最大2作品の画像とタイトルを横に並べます。対象作品とほかの作品の7項目について差の絶対値を合計し、小さい順に選びます。本人は除き、同じ差なら作品ID順で安定させます。これは作品同士の持ち味の近さで、読者への推薦の次点や適合率とは呼びません。

選ぶと、ランキングと共通の短い紹介ポップアップで画像・タイトル・作者の既存紹介文・pixiv本文リンクを表示します。ここからさらに関連作品や詳細ページへ進む入口は置きません。小表示用画像を再利用し、閉じるボタン・Esc・枠外クリックで閉じ、元の作品へフォーカスを戻します。

関連作品を見ても、診断の紹介履歴・初回推薦数・今月の足跡・全作品紹介の進行には加えません。その作品が後の診断で改めて推薦されることは許します。pixivへ進んだ場合だけ、関連作品経由と区別して本文リンク利用を記録し、「みんなが選んだ」には合算します。詳しくは[アクセス解析と公開集計](analytics.md)を参照してください。

## 公開ランキングと来訪カウンター

「みんなへのお薦め」画面の上部には「青娥のお薦め」「みんなが選んだ」のタブを置きます。前者は各回の初回推薦数、後者はpixiv本文リンク利用数です。どちらも「最近のお薦め」（本日を含む直近7暦日）を上、「今まで」（計測開始日以降）を下に置きます。各集計の厳密な定義、重複防止、結果カードの今月の足跡は[アクセス解析と公開集計](analytics.md)を参照してください。

各期間は、順位・作品画像・「18回」のような回数だけを縦にまとめたカードを横に並べます。表示領域を作品数に合わせて広げず、収まらない分はその列の中で横スクロールします。上位3位までを同率込みで表示し、同率の作品を削って3作品へ絞りません。順位は同率の作品数分だけ次の順位を飛ばします（例：1位・1位・3位）。

余白と画像の大きさを画面の高さに合わせ、ランキングのウィンドウが一画面に収まりやすくなるよう調整します。来訪カウンターとフッターまで一画面に収めることは要件に含めません。具体的な日付範囲、累計開始日、画像の押下・横スクロールの操作説明はランキングに常時表示せず、集計の種類を説明する一文と小さな更新日時を残します。小さい画面や文字拡大時には自然に縦スクロールでき、内容を固定高さで切り捨てません。

作品画像を選ぶと、イメージ画・タイトル・作者の既存キャプション・pixiv本文リンクをネイティブの `dialog` で開きます。利用者の回答に基づく推薦理由は付けません。幅600pxより広い画面では幅200pxの画像を左、タイトルと紹介文・リンクを右に配置します。600px以下では幅140pxの画像を中央に置き、その下にタイトル・紹介文・リンクを並べます。既存の小表示用画像を再利用し、ここでは拡大用画像を読み込みません。

ポップアップは閉じるボタン・Escキー・枠外のクリックで閉じ、開いた画像へフォーカスを戻します。開いている間は背後のページのスクロールを止め、画面移動時には閉じます。画像が取得できない場合もタイトル・紹介文・本文リンクを残します。タブは矢印キー・Home・Endでも切り替えられ、画像の選択やタブ切替自体は本文リンク利用として計測しません。

来訪カウンターは画面本体の下、フッターの前に置き、「この書斎への訪問」と本日・累計の訪問回数を表示します。書斎に合わせた明るい紙と左右の軸を持つ巻物風の枠をCSSで描きます。更新日時と計測開始日はカウンターに残し、ランキング側で期間表示を省く方針とは区別します。

## 結果の共有

現在の結果と過去の結果から、「この結果を共有」で同じ共有ダイアログを開きます。共有文を読み取り専用の欄に表示し、次の2つの操作を用意します。

- **Xで共有**：`https://x.com/intent/tweet` の `text` パラメーターに共有文を渡し、投稿画面を新しいタブで開きます。投稿を自動確定する処理はありません。
- **共有文をコピー**：Clipboard APIでコピーします。利用できない場合は共有文全体を選択し、端末のコピー操作を案内します。成功・失敗時の案内は読み上げにも通知します。

共有文は次の形式です。URLは `presentation.site_url` の公開サイト入口を使い、ローカルURL、タブ内の結果ID、回答内容を含めません。受け取った人は、自分の案内を始められます。

```text
青娥に薦められたお話は
『作品名』でした。

あなたにはどんなお話が出るでしょう？
#青娥の小説案内 #東方Project
https://lapis-stein.github.io/Kakuseigar/
```

共有ダイアログも閉じるボタン・Escキー・外側のクリックに対応し、閉じると操作元へフォーカスを戻します。スマホ幅ではXとコピーのボタンを縦に並べます。作品ごとの画像を投稿へ添付する処理はありません。リンクの紹介画像には `index.html` のサイト共通OG画像を使います。

## 実績と案内役への操作

全作品の紹介を受けた場合は最後の結果のお祝い欄から実績を共有できます。通常の一作品の共有は別の操作として残します。履歴から最後の結果を開いた場合も同じ共有が可能です。件数は開始時の作品一覧に基づく結果の `totalWorks`、達成判定は `isLast` を使い、専用の保存フラグは追加しません。

`src/sharing.js` は作品・実績の共有文と共通ダイアログを担当します。X投稿画面とコピーには同じ全文を渡し、閉じたダイアログへ遅れてコピー結果を表示しないようにしています。

`src/narrator-interaction.js` は案内役への操作状態を管理し、推薦計算やDOMから独立しています。保存先は `kakuseigar:narrator:v1` で、推薦の保存キーを共有しません。素材の差し替えと実績画面への切替は通常の描画で行い、演出の待機や専用の入力ロックはありません。案内へ復帰すると押下状態だけをリセットし、回答・紹介履歴は維持します。推薦データの版が変わり新規開始となる場合は、こちらも新規化します。

## ビルドと更新

解析と公開集計の定義、Google側の設定、定期更新の有効化手順は[アクセス解析と公開集計](analytics.md)を参照してください。公開JSONは個別の利用履歴を含まず、未設定時は実測値を表示しません。

`node scripts/build.mjs` は公開に必要なファイルだけを `dist/` に集めます。プロジェクトのサブディレクトリ配下でも動く相対URLを使い、画面切替にサーバー側のルーティングを必要としません。

公開は `main` を対象とする集計ワークフローが毎時00分、または手動実行時に行います。Pushだけでは即時公開されません。検証・集計・ビルドがすべて成功した場合にアプリと集計を一緒に反映し、失敗時は直前の公開内容を維持します。画面確認用の仮データやスクリーンショットは `test-results/` に置き、公開物へ含めません。

作品を追加するときは、制作資料側で作品情報と推薦根拠を整理し、公開用データを書き出して確認します。制作資料一式をこのリポジトリへ移す必要はありません。
